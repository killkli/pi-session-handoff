回顧這個 session，找出讓工作變慢或讓你走錯方向的地方，提出「改善下次工作環境」的建議。

限制：

- 只根據本 session **實際遇到**的阻礙，不要從專案結構去推測問題。
- 不要再去搜尋或讀 repo，只用你對這個 session 的記憶。
- 如果沒有實際遇到阻礙，就只回「本次無具體阻礙」，不要硬湊。

依下列分類檢查，每項格式為「發現 → 證據（本次哪裡發生）→ 建議改法」：

1. **導覽**：找某個檔案或資訊花很久 → 在最近的 `AGENTS.md`（或子目錄 `AGENTS.md`）加指引。
2. **機械性錯誤**：固定模式的錯（路徑、API、import、命名、指令呼叫方式）→ 優先建議做成
   lint、專案的驗證腳本或 Pi extension（`.pi/extensions/`），而不是寫成文字規則。
3. **不明顯的知識**：環境怪癖、隱性相依、必須照順序做的步驟 → 寫進離相關程式碼最近的
   `AGENTS.md`；跨模組的慣例才留在根目錄那份。
4. **過期或無效的指示**：`AGENTS.md` 裡哪一條錯了、或從頭到尾沒用到 → 建議刪除或修正。
5. **交接協定本身**：注入太吵、門檻太鬆太緊、段落不合用 → 改 `.pi/handoff.json`
   （`staleMinutes`、`nagOnSettle`、`handoffPath`、`verifyCommand`），不要改碼。

聚焦範圍：${@:-整個 session 的所有工作}

輸出要求：

- 依嚴重度排序（會卡住工作的排最前）。
- 每項給出「要改哪個檔案、加什麼內容」的具體草稿。
- **先列給我看，等我同意後再寫入**；未經同意不要動任何檔案。
