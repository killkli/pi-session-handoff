# 規格：50% 前自動壓縮並交接

狀態：**待實作**。本文件給 Pi agent 實作；目前 bundle 只在壓縮前備份，尚不會依此規格觸發壓縮或產生交接。

## 目標與範圍

在同一 Pi session 持續工作時，依目前模型的 context window 提早自動壓縮，並在壓縮前產生可接續工作的交接。壓縮後 agent 要繼續原本使用者的任務，不是開啟新 session、等待使用者確認，也不是把快照當成交接。此功能是本 bundle 的 Pi extension，不改 Pi 核心或 omp bundle。

## 行為契約

1. 預設啟用；以目前模型的 context window 為分母、目前有效 context token 數為分子，而不是累積用量或固定 token 數。預設在 **40%** 時啟動流程，保留到 50% 的餘裕供交接與壓縮；不要等到 50%。在可安全介入的最早時點檢查，包含長時間、多工具呼叫的 agent run，而不只是在使用者重新發話或 session 結束時檢查。resume、分支切換及模型切換後，要重新依當前分支與模型計算；首次觀察已達門檻也要觸發，不依賴先前從門檻以下跨越的樣本。
2. 這是盡力提早觸發，不是假稱硬上限：token 使用量可能只是估算，單一大型輸入／工具結果或模型切換也可能直接跨過 50%。若首次觀察已達或超過 50%，仍應在下一個可安全介入的時點執行流程並明確告知使用者；不得丟棄輸入或假裝未超限。使用量或模型 context window 未知、無效時不得猜測；明確提示並在後續可取得有效數據時再檢查。
3. 先讓 agent 依現有 `/wrap` 的八段格式，**整份重寫**已設定 `handoffPath`（預設 `docs/HANDOFF.md`）。內容至少保留原始目標、已完成及未完成事項、具體下一步、決策與理由、失敗嘗試、待確認事項、實際驗證結果；沒有的段落寫「無」。沿用現有 80 行限制與真實事實規則。這是中途交接：不要求使用者確認、不自行 commit、不因交接中斷原任務。交接完成後再壓縮；不得只複製舊交接或在 shutdown hook 呼叫模型冒充完成。
4. 壓縮產生的 **session context summary 本身也必須是可接續的 handoff**，保留上述任務狀態、限制、檔案路徑、驗證與下一步，並指向剛更新的交接檔；不能只在磁碟留下交接檔、讓壓縮後模型失去任務。保留 Pi 的正常 compaction entry、最近訊息與既有摘要的延續語義。壓縮成功後在同一 session 自動繼續原任務，不重跑已完成的副作用。
5. 同一 session／分支一次只能有一個自動交接或壓縮流程。交接及壓縮產生的 turn 不可再遞迴觸發；成功後重新量測，若壓縮仍高於門檻，不得無限循環。失敗、取消、無可壓縮內容或壓縮後未降至門檻時，要清楚報告並釋放流程狀態；不得宣稱成功、吞掉錯誤或在每個 turn 忙碌重試。後續有新進展或使用者重試時可再次評估。
6. 寫入交接失敗時，不得覆蓋有效舊檔為部分內容，也不得把它說成新交接；顯示錯誤並保持原任務可繼續。不得為了這項功能取消或阻擋 Pi 原有手動 `/compact`、原生自動壓縮、溢位恢復與現有 `session_before_compact` 快照；這些流程與自動流程碰撞時不得重複壓縮或破壞彼此結果。
7. 尊重 Pi 對自動壓縮的停用設定，且提供本 bundle 自己的停用開關；停用後不啟動本自動流程，手動壓縮及快照照常。設定遵循既有 `handoff.json` 載入、初始化及 `/handoff-reload` 慣例；更新 README、技能文件與 CHANGELOG，區分中途自動交接和收尾 `/wrap`。UI 與非互動模式均須可用，不依賴彈窗或使用者輸入。

## Pi API 與實作注意

- 實作前先對目標 Pi 版本核對 extension API。Pi 的 `ctx.getContextUsage()` 使用最近 assistant usage 並估算尾端訊息；`turn_end` 是一個可觀察工具結果後狀態的時點，但需處理活動 turn、佇列、resume、分支與並行的實際語義。
- `ctx.compact({ customInstructions, onComplete, onError })` 不會 await 完成；應以完成／失敗事件或 callback 管理狀態，並確保 handoff 的生成與寫入先完成。不得在 active run 或 callback 中假設同步壓縮成功。可參考 Pi 隨附的 `examples/extensions/trigger-compact.ts` 與 `docs/compaction.md`；依實際支援的 API 選擇安全排程方式。
- 目前 `extensions/session-handoff.ts` 的 `session_before_compact` 只做 transcript 與現有 handoff 的快照，且備份失敗不阻擋壓縮。保留該行為；快照不是更新 handoff。若使用 Pi 內建壓縮與 custom instructions，確認指示確實進入摘要請求並保留既有摘要及檔案追蹤；若自訂摘要，必須同等保留這些語義。
- 原本 `/wrap` prompt 是收尾用，會要求使用者確認下一步與考慮提交；自動流程不可直接照搬這些互動指示。新流程應重用格式與事實規則，不改變手動 `/wrap` 的契約。

## 驗收

使用隔離的暫存專案與可控 Pi context／模型；測試不需真實模型服務，並至少覆蓋：

- 39% 不觸發、40% 觸發，首次觀察已超過門檻也觸發；不同 context window、模型切換、resume／分支切換和長工具循環皆以當前狀態計算。
- 交接檔依自訂路徑更新且具八段與實際任務狀態；先成功寫入才呼叫壓縮；壓縮摘要帶交接與原任務，完成後同一 session 繼續而不等人或重複副作用。
- 未知使用量、直接超過 50%、檔案寫入錯誤、壓縮失敗／取消、壓縮無進展，均有可觀察結果，不遞迴、不卡住、不丟失舊交接或冒稱成功；同時觸發及原生壓縮競爭不重複執行。
- 停用設定、非互動模式、手動壓縮、既有壓縮快照與原生溢位恢復不退化；使用真實 Pi extension 載入及受控執行驗證事件順序與接續行為，不只檢查 prompt 字串或 mock 呼叫次數。
